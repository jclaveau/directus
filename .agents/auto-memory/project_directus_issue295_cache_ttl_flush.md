Original design (kept for the rationale):

**Goal.** Retune cache TTL from the `/settings/cache` page ([[project_directus_cache_admin_page]]) live across all nodes, + a flush button beside it (TTL change only affects NEW entries — stamped per-entry at write time — so pair with flush).

**Three parts + settled decisions (do NOT re-litigate in a fresh review):**
1. **Persisted live global TTL.** New nullable `directus_settings.cache_ttl` (free string, `getMilliseconds` grammar). `null`→inherit env `CACHE_TTL`; `0`→no expiry (matches existing `getMilliseconds(…,0)`). Hot-path read = a module-level `cacheTtlOverride` mirror (same shape as `cacheStatsActive()`), seeded at boot, read as `cacheTtlOverride ?? env['CACHE_TTL']` at respond.ts (per-entry `expiresAt`) / scoped-cache.ts (redis key expiry) / cache.ts (Keyv default). Live-flip via a **`cacheConfigChanged` bus message** (template = existing `schemaChanged` / `extensions.reload` / `cacheStatsToggled` / `cacheTtlRulesChanged`). Likely NO Keyv recreation needed (per-entry expiry from the live var) — confirm no `set()` relies solely on Keyv's constructor TTL. `useEnv()` is an immutable boot snapshot (no reload) → that's WHY the override must be a settings-backed mirror, not env.
2. **Flush button = per-target multiselect** (blanket flush is the wrong default — system cache is auto-invalidated on schema change + costly to drop). Targets, with defaults jean settled:
   - **`Response cache`** default **ON** — `scalabus_response:*` AND its scoped-tag index `scalabus:tag:*`, as ONE unit (the everyday "data went stale" intent).
   - **`System cache`** default **OFF** — one collapsed toggle for schema+collections+permissions (the `clearSystemCache()` set; permissions depend on schema so never a partial subset).
   - **`Locks / build-identity`** default **OFF**, warned — `scalabus_lock:*`; clearing drops the build-identity fingerprint → forces re-flush next boot.
   Server: `clearCache({ targets })` / `POST /utils/cache/clear?targets=…`, enum-validated, default `Response cache`; bus carries the SAME `targets` so every node clears the identical per-node memory-tier subset. Out of scope: `scalabus:stats*` (own `/cache/stats/truncate`) and cross-`CACHE_NAMESPACE` flush (would need FLUSHDB/broad SCAN — cross-tenant-dangerous, not cluster-safe).
3. **Per-user localStorage of the checked targets** (pure UI pref → not env/settings, [[feedback_view_filter_not_config]]) keyed `cache-flush-targets:<userId>` via `useUserStore()`, restore-on-mount / persist-on-change, so chained purges keep the last subset. Both TTL-edit + flush are **admin-only**.

**The flushCaches scoped-tag orphan gap (real codebase fact, the design's gap-to-fix).** `flushCaches()`→`cache.clear()` clears the Keyv `scalabus_response` namespace but NOT the raw-redis `scalabus:tag:*` SET keys — those are written direct via ioredis `sadd` (scoped-cache.ts), OUTSIDE any Keyv namespace, so a namespace `clear()` never scans them. They linger as orphan pointers until `ttl*2` self-expiry (harmless — next purge's `smembers`→`cache.delete` no-ops). NB this is distinct from scoped PURGE, which IS transparent to the `_response` split ([[project_directus_cache_namespaces]]) because it deletes members by key, not by namespace-clear. So the `Response cache` flush must ALSO `SCAN + DEL scalabus:tag:*` (reuse `scanScopedCacheTagKeys`).

**Overlap with #279 (must reconcile before building).** [[project_directus_cache_ttl_rules]] (#279, PARKED draft) already replaces the global `CACHE_TTL` with a per-path/method/query-shape RULES TABLE + `cacheTtlRulesChanged` bus. #295 is the SIMPLER global-override direction (one settings value, not a rule set). They conflict on "what overrides env TTL" — pick one (or make #295's global the fallback under #279's rules) rather than shipping both. jean designed #295 fresh without invoking #279; flag the overlap when either is un-parked.
