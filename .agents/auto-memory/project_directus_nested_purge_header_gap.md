Nested creates (a parent's A2O field → a nested collection) purge the nested item's slices for real, but `x-scoped-cache-purged-tags` is built from the ROOT service's `scopedCachePurged` only (`api/src/middleware/respond.ts:99`, `controllers/items.ts`). Nested services' purges never reach the header.

**Why:** A consumer PR's item 7 (one nested create instead of two) turned the scenario "A review-round write purges its own scoped-cache slices" red: header lacked the 7 nested-collection tags. Probe (temporary cached read MISS→HIT→MISS after the nested create, returned new round id 180) proved no stale data: header-only gap.

**How to apply:** don't treat a missing tag in that header as stale-cache (HIGH) until a stale-read probe says so. Fork fix in progress (2026-11-11): AsyncLocalStorage store for purged tags, same shape as `queryAuditStore` behind X-Query-Audit, header aggregates nested purges. Regression test red-first.
