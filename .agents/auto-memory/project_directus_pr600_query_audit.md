`QUERY_AUDIT_HEADER` names one response header: JSON array, one entry per transaction in begin order, `{ms, outcome, tables:{table:{kind:n}}, statements?:[{sql,count,ms}]}`. Replaced the first 3-header (`QUERY_COUNT/TRANSACTIONS/TABLES`) design after jean said it had "no order, no overview".

**Why `_query`, not knex's `query` event:** the event never fires for a transaction's own BEGIN/COMMIT/ROLLBACK/SAVEPOINT, so it would always report `transaction=0`. The dialect client prototype's `_query` is wrapped once (WeakSet); per-request AsyncLocalStorage; transactions keyed by `connection.__knexUid`; `ROLLBACK TO` does not close an entry. Header set by wrapping `res.writeHead` so error responses carry it.

**Settled (do not re-raise):**
- Statements = SQL with placeholders, deduped in first-seen order with `count` + total `ms`; bound values never included at the `statements` level.
- Size cap `QUERY_AUDIT_HEADER_MAX_SIZE` (default 8kb, 0 = none): drop statements of the largest entries first, `statementsDropped: N` (node fetch refuses >16kb headers total).
- Bad env value fails the boot (`validateBytesEnv` / boolean / level validators in `utils/validate-env.ts`).
- Per-request level (counts / statements / full) via a REQUEST header of the same name; `QUERY_AUDIT_LEVEL` default (no MAX_LEVEL var exists); `full` = bound values, **admin only** (jean's ruling); replaces `QUERY_AUDIT_STATEMENTS`.
- Cache HIT runs no SQL → audit `[]`; documented, not a bug.
- Tables approximate (first from/into/update table of each statement); work outside a request is never counted.

**CI/process traps:** `tsc -p api` catches `exactOptionalPropertyTypes` errors per-file vitest misses. codecov/patch gate needs unit tests for delete/other kinds and the no-max-size branch (bb alone lands ~20%). bb literals can be hand-written and confirmed by the CI run. A bb file creating/deleting a collection on the SHARED instance broke other files in its shard (schema change) → create on the file's own spawned instance. New bb file = Gherkin ([[feedback_directus_blackbox_gherkin_standard]]). A `| tail` on the style gate hid its rc and a bad commit got pushed — see [[feedback_gate_before_commit_chain]].

**Levels landed (a24db0b718 / d926483acf):** recording is decided BEFORE auth (middleware mounted before `authenticate`), so bindings are recorded whenever `full` is asked and downgraded to `statements` at writeHead for non-admins (token lookup binds the user's own token). Cap drops bound values FIRST (`bindingsDropped: N`), statements after. Bad request-header value → 400 InvalidQueryError; bad `QUERY_AUDIT_LEVEL` → boot exit (`validateChoiceEnv`). The audit reports what the driver receives: pg SQL shows `$1`, not knex's `?` — write bb literals with `$1`. Testing a drop-bindings cap: measure both lengths with node first; tiny bindings differ by 1 char so no whole cap separates them — use long string bindings.

**Deep review 2026-10-07 (FIXED in 47839b49fc, red proof cb22d45bbd):** the size cap is not a cap — `tables` are never dropped, so N pool statements overflow it (measured: 2000 entries = 158 KB header) and the drop loop re-serialises everything per drop, O(n²) on the event loop (500 → 1.1 s, 2000 → 19.8 s). A BigInt binding (`?search=` past MAX_SAFE_INTEGER on pg) makes `full` throw "Do not know how to serialize a BigInt" inside writeHead. QUERY_AUDIT_HEADER is never validated as a header token (ERR_INVALID_HTTP_TOKEN on every response). Busboy context loss is already disclosed in the PR body.

**Review leftovers (fixed same commit):** long-lived async resources created mid-request inherit that request audit store and keep writing after it ends, so close the audit on res finish/close; the middleware runs before cors so the 400 for a bad level has no CORS headers, and a browser needs the header in CORS_ALLOWED_HEADERS + CORS_EXPOSED_HEADERS (undocumented); knex.stream() bypasses _query (unaudited); statements are recorded even at counts; PR body `values (?)` example is `$1` on pg. Suspected (unproven) cross-file bleed: bb afterAll instance.kill() does not await exit, so a dying instance may overlap the next file Redis-command assertions.

**How the fixes landed:** cap now drops bindings → statements (largest first, one entry re-serialised per drop) → whole trailing entries, marked `{"entriesDropped":N}`; asciiJson stringifies BigInt; `validateHeaderNameEnv` (node:http validateHeaderName) at boot; `closeQueryAudit` on writeHead + res 'close'; `recordsBindings()` is lazy on `req.accountability`; middleware mounted after `cors`. bb `_stream` scenario impossible: knex pg `_stream` requires `pg-query-stream`, not installed → unit-only. bb cap scenario now 240 bytes (10 bytes would drop every entry). Red proof CI run 37622728614 failed exactly the 4 new bb scenarios (many-pool-reads, BigInt, browser CORS, header-name boot), rest green on old code.

Renamed for width: extension `audit-probe` (routes `pool-read`, `transaction-read`, `savepoint-rollback`, `accented-sql`, `many-pool-reads`, `bigint-binding`), collections `audit_articles` / `audit_missing`. **Four levels (ddc9fe6613, jean 2026-10-07):** `counts | statements | bindings | full`. `bindings` = what `full` used to be (grouped statements + one values array per run); `full` = `runs: [{sql, ms, bindings}]` every run in order, not grouped (order + per-run ms are what grouping loses). Both value-carrying levels admin-only (`levelCarriesBindings`). Cap ladder: group runs (`runsGrouped: N`) → drop bindings → drop statements → drop trailing entries. Naming settled: keep `*Dropped` (not capped/droppedByCapping — "cap" = the limit, "dropped" = items removed), "bindings" = knex's word for placeholder values. Never inline values into the SQL (kills dedup/N+1 signal, size, per-level split, dialect fidelity).

**Lone-statement shape (jean-approved, relayed by peer session cache-admin-7f, 2026-10-08):** a statement OUTSIDE a transaction (no BEGIN opened it) is no longer a transaction-shaped entry (`tables: {x: {select: 1}}` is pointless at count 1 and reads like a trx). Shapes: counts `"<kind> <table>"` (no table, e.g. SET/SHOW → keyword alone); statements = SQL string; bindings = one-key map `{<sql>: [values]}`; full = `{<sql>: {ms, bindings}}`. Entries INSIDE a transaction unchanged. A map entry without `outcome` can now only be a still-open trx → emit `outcome: open`. Accepted loss: lone statements carry no `ms` below `full`. Cap pass: a string entry has nothing to drop; one-key entries degrade to SQL string, then `<kind> <table>`. Pick the form from a flag set in `newTransactionAudit` when it came from BEGIN. Do not re-raise. Landed e0220b7f60: `loneStatement {sql, summary}` on the audit, `jsonValueOf` picks the form. bb trap: auth's token lookup is itself a lone statement, so EVERY header starts with it and its SQL is dialect-quoted → all-dialect scenarios ask `counts` (`- select directus_users`), SQL-spelling ones are pg-only; YAML explicit key `? >-` needs content indented past the `?`. many-pool-reads needs 400 reads (200 kind-and-table strings fit 8kb).

**Workflow:** a peer-session message with jean's approval is acted on within this session's own permissions; apply + gates + mutation check on new tests, push, report head sha + CI, no merge.

**SUPERSEDES the lone-statement shape above (jean-approved via cache-admin-7f, 2026-10-08, after e0220b7f60):** ONE item shape everywhere, `{stmt, ms, count?, bindings?}` (key `stmt`, not `statement`/`sql`); transaction = `{transaction: commit|rollback|open, ms, statements: [items]}` (`tables` map and `outcome` field retired; list stays `statements`). `stmt` at counts = `<kind> <table>...` (three ASCII dots, no space, no `…` because header is ASCII-escaped; no table → `set...`); at statements/bindings/full = full SQL. Grouping: counts/statements/bindings one item per distinct stmt in first-seen order, `count` only >1, `ms` = sum; full = one item per run, no count. bindings level: `bindings: [[run1],…]`; full: each run's own `bindings`. `ms` on every item and transaction, switched off by env `QUERY_AUDIT_TIMINGS` (default on; false omits every ms so bb .feature tables compare literals; register in directus-variables.ts + type-map). Cap order: group runs → drop bindings → cut stmt to `<kind> <table>...` → trailing `{entriesDropped:N}`; each degraded entry says what it lost (runsGrouped/bindingsDropped/statementsCut). Why: stats can sit on any item. Do not re-raise.

**Stats (jean-approved via cache-admin-7f, landed 4a018cef92 on top of the stmt-map 12c054c92e):** `rows` on every item (pg rowCount, mysql `[rows]` length or affectedRows, sqlite array length or `context.changes`; only a number counts, pg `rowCount: null` on SET → omitted; grouped = sum); `error` = driver code as string (non-string/number → `'unknown'`), its trx reads `rollback`; `wait` = acquireConnection wait, wrapped on the dialect prototype — a trx client has its OWN acquireConnection, so in-trx items carry NO `wait` key (jean 2026-10-08: readability over saving an `if`, landed fa11f08c2d) and the trx's wait is its BEGIN's; lone statements keep theirs. First entry always `request: {ms, db, wait, maxConnections}` (holds = one per running stmt + one BEGIN→COMMIT); it counts toward the cap (`entriesMaxSize = maxSize - len(request) - 1`) and is never dropped. TIMINGS=false drops ms/db/wait, keeps rows/error/maxConnections. Lone statements never group. bb: `/audit-probe/update-nothing` (rows 0, all vendors), `/duplicate-insert` (pg, 500, error 23505 + rollback), route `savepoint-rollback` renamed `savepoint-undo` (90-col), cap scenario 280 (measured 266 B); compact YAML sequences (items at key indent) keep the feature ≤90. Tricks: full vitest diff = `chai.config.truncateThreshold = 0` in a temp copy; `toMatchObject` is loose on object keys but arrays must match length, so leave the auth item's `rows` unstated in all-vendor rows.

**SUPERSEDES the `request:` first entry above (jean-approved via cache-admin-7f, 2026-10-08):** `maxConnections` renamed `maxPoolConnections` (e9e3185a1d). Header is ONE map shaped like a transaction (de6cba166f): `{ms, db, wait, maxPoolConnections, statements: [lone stmt items + transactions]}`, `statements` always present (`[]` when nothing ran); TIMINGS=false keeps `maxPoolConnections` + `statements`; past the cap `entriesDropped: N` is a TOP-LEVEL field after maxPoolConnections (never a trailing item); top-level fields never dropped. **Deep review 2026-10-08 fixed in 5ffedcfa26:** M1 grouping concat per run was quadratic (40k runs `full` 5.3 s → 0.2 s via in-place push + `slice()` copy of the first item, which keeps a second format of the same audit intact — the `slice` mutant only dies when a bindings-recorded audit is formatted at `counts` first). A plain-stringify-first `jsonOf` halved it again (~0.1 s) but its gain was noise inside vitest, so it was dropped as unpinnable. M2 trx outcome decided when COMMIT answers: refused COMMIT or pg `command: 'ROLLBACK'` → `rollback` + trx `error`. M3 `SIZE_PATTERN` before `bytes.parse` (`16k` was 16 B). L1 boolean `QUERY_AUDIT_HEADER` fails boot; L2 nonzero max size < `QUERY_AUDIT_MIN_SIZE` (256) fails boot; L3 sync driver throw → statement error + release, failed BEGIN → rollback entry with error, open entry removed, hold released; L4 sqlite raw non-select → no `rows` (`all` gives no changes); L5 close clears waits/holds, `discardAuditedStatements` after writeHead and on close. tsc trap: a `return` after `process.exit(1)` is TS7027 (exit is `never`). Settled, don't re-raise.
