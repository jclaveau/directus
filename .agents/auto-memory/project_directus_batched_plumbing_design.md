Rule: only consumers call `createOne|updateOne|upsertOne|deleteOne`; inner plumbing (items.ts, payload.ts, controllers, auth, CLI, system services) uses `createMany` / `updateGroups` / `upsertMany` / `deleteMany`. Singulars become thin wrappers over the plural. Enforced by `no-restricted-syntax` on the method name in `api/src/**` (tests excluded); `RelationsService`/`ExtensionsService` have no plural → `eslint-disable-next-line` with reason.

**Decisions by jean (2026-10-16):** scope = ALL of `api/src` (~60 files); `deleteOne` included; hooks: ALL filters run before any insert (no per-child ordering opt) → planner `Model.ts` dedup must dedupe within its own entries list.

**Why:** #414 (nested writes = N single-row inserts, `processO2M/M2O`, `upsertMany`), #606, #335. Registration case 844 parents × 2 children: 1688 inserts + 844 deselects + 8440 snapshot queries today → ~1 each batched.

**Landmine (first PR):** 7 system services hold logic only in `createOne` override (shares validateAccess, translations dup check, access UserLimits, flows reload, users, versions, permissions). Array POST goes to `createMany` and skips it — suspected security bug (`controllers/shares.ts:105`), NOT reproduced yet. Move logic into plural methods + lint-ban `override createOne|updateOne|upsertOne|deleteOne`.

**PR split:** 1 overrides→plural + shares/translations/flows fix; 2 batched `upsertMany` (one `WHERE pk IN`, updates before creates, split runs at repeated new key); 3 `processO2M` over all parents, then M2O/A2O over all rows; 4 lint rule + mechanical sweep (Sonnet subagent). Pin query counts with `QUERY_COUNT_HEADER` (#599) in bb tests written BEFORE the refactor.

**Known accepted differences:** one deselect query across parents differs only if a hook takes over/cancels a child (document, don't handle); IN lists chunk under 65535 bind params; merging identical nested items is #606/#337, out of scope.

**Coverage PR (started 2026-10-16):** worktree `~/.herdr/worktrees/directus-cms-2/cover-nested-writes`, branch `v11.10.1-test/cover-nested-writes` off hhh-dev; round 1 = 3 subagent areas (nested M2O/A2O + upsertSingleton + uuid/`'all'` batch create; O2M array/alterations/multi-parent/M2M; system singular overrides + deleteOne). Do NOT pin the shares-array bypass (a bug) nor child-ordering hook behaviour (changes by decision). Baseline bb per-flag coverage at hhh-dev 2ab8b84: items.ts 83.7%, payload.ts 79%, shares 5%, translations 0%, versions 0%, users 21%. Shares/translations/flows array-bypass issue not yet offered for filing.

**Statement order (jean, 2026-11-06, issue #689):** hooks stay batched in every mode except `disableBatching`. `mutationBatching: 'minimizeMutations' (default) | 'preserveMutationOrder' | 'disableBatching'` chooses the write order: the default writes every update and then every create per run, `preserveMutationOrder` keeps payload order with consecutive same-kind payloads sharing a write (opt-in, rare, can only be slower), and `disableBatching` restores the per-payload behaviour from before batching. Default priority: request > collection `defaultMutationBatching` > env `DEFAULT_MUTATION_BATCHING` > `minimizeMutations`; exposed over REST and the SDK. Don't re-propose a "per-row hooks, batched writes" value (ruled overengineered).
